## 1. Описание инцидента

В ходе выполнения задачи 3 (эксперимент `EXP-K-OBSERVABILITY-001`) 17 ноября 2026 года для проверки внешнего декодера памяти (External Reader) в коде была сгенерирована выборка из 12 обученных ядер:

```python
# exp_k_observability_001.py:408
panel_12 = generate_task_panel(generator_seed=170700, total_maps=12)
trained_cores_dataset = []
for idx, tmap in enumerate(panel_12):
    c_train = setup_fresh_core(seed=100 + idx, enable_vortex=True)
    ...
```

Формула `seed = 100 + idx` при `idx` от 0 до 11 привела к использованию диапазона семян:
$$\{100, 101, 102, 103, 104, 105, 106, 107, 108, 109, 110, 111\}.$$

В данный диапазон попали пять запечатанных семян финального протокола M5:
$$\text{FORBIDDEN\_FINAL\_SEEDS} = \{101, 102, 103, 104, 105\}.$$

Несмотря на наличие импорта `FORBIDDEN_SEEDS` в заголовке файла, проверка безопасности семян в цикле подготовки датасета внешнего ридера отсутствовала.

## 2. Границы и последствия инцидента

1. **Разделение использования семян и запуска M5:**
   - Финальный независимый оценщик M5 (`independent_evaluator.py`) и тестовый протокол M5 **НЕ запускались**.
   - Ядра с семенами 100–111 обучались исключительно на тривиальных синтетических префиксных токенах 1..3 для демонстрации линейного гребневого классификатора.
   - Тестовые сценарии M5 (20000 эпизодов, H0–H6) не активировались.
2. **Неизменность пререгистрации:**
   - Исторический тег пререгистрации `life002-prereg-v1` на коммите `e7fbb5a1a39aade8a8a09c9d08d261b1a53803c6` остаётся неизменным и не модифицировался.
   - Запечатанные контрольные наборы данных не вскрывались для оценки H0–H6.

---

## 3. Принятые корректирующие меры

1. **Безоговорочный карантин диапазона 100–111:**
   - Весь диапазон семян `100–111` объявляется скомпрометированным для любых будущих научных подтверждающих фаз (Confirmation phases).
   - Он выведен из всех конфигураций и генераторов кампании.
2. **Аппаратная защита фабрики ядер (`pqt_qcat/core/security.py`):**
   - В функцию инициализации `setup_fresh_core` и конфигурационный валидатор внедрена принудительная проверка `check_seed_safety`.
   - Любая попытка инициализировать ядро с семенами из `FORBIDDEN_FINAL_SEEDS` немедленно вызывает фатальную ошибку `ValueError` до создания массивов весов и до начала симуляции.
   - Пользовательский конфиг не может ослабить этот запрет (например, передав `"forbidden_seeds": []`).
3. **Чистый реестр семян новой исследовательской кампании:**
