# MEMORY-LOCATION-001: запись и доступ к памяти

Исполнитель: Codex. Дата: 18 ноября 2026. Основа: 55ec3f8.
Новая ветка: `fix/codex-memory-location-001`; исторические результаты не перезаписываются.

## Вопрос

После непрерывного обучения одного правила содержится ли информация в K и можно ли
извлечь её (a) из живого Z, (b) после сброса только Z, (c) независимым внешним reader?
Это диагностический опыт. Он не подтверждает LIFE для двух правил, необходимость A,
сон, глобальную устойчивость или сознание.

## Зафиксированный дизайн

Машинный первоисточник — `PLAN.json` в `C:\AGI\PQT_QCAT_AUDIT\CODEX_MEMORY_LOCATION_001_RUN_B`.
Первый каталог RUN_A закрыт до обучения: во время preflight исправлена передача RNG
интегратору, поэтому source hashes были зафиксированы заново. Выборки и гиперпараметры
не менялись по научным результатам.

- Два training режима: CARRY и RESET. RESET — положительный диагностический контроль,
  не выполнение требования непрерывной жизни.
- 72 сбалансированных события, 6 query, 4 класса; контекстный импульс отсутствует.
  Query 8 физических ticks, gate=1, два подшага по 0,005 на tick, eta=0,8, clip=0,5.
- Development: seeds 810001/810002, 12 fit maps + 4 tune maps; maps не пересекаются.
- Holdout: seeds 810101–810104 × 8 новых maps. Итого 64 development и 64 holdout жизни
  с учётом двух режимов. Инициализация и порядок событий парные между CARRY/RESET.
- Все 24 mappings различны, содержат 4 класса. Fit покрывает все классы для каждого
  query. Панель зафиксирована до измерений, генератор 810201. M5 не используется.
- Checkpoints 0/24/48/72. Primary endpoint — 72; промежуточные точки диагностические.

## Чтение одного checkpoint

Для каждого из шести запросов создаётся отдельный одинаковый clone checkpoint.
Live probe сохраняет его Z; reset probe заменяет только Z на исходное и очищает trace.
K/B/W неизменны, обратной связи и изменения весов в probe нет. Таким образом,
результат не зависит от накопленного воздействия предыдущих probe queries.
Training branch не изменяется диагностикой. Для RESET-training live probe всё равно
принудительно использует carry: измеряется влияние фактически сохранённого Z.

Внешний reader получает 144 активные координаты K, отдельно K_initial и ΔK.
Для каждого training режима используются независимые 6 RidgeClassifier. Alpha
выбирается из фиксированной сетки только по development tune; затем refit на всём
development. Сохраняются coefficients/classes/intercepts и hash до holdout.
Никакой настройки по holdout. Majority определяется по development, не по test.

## Анализ

Accuracy, margin, NLL штатного считывания; accuracy внешнего reader; фактические ΔK,
предсказания до feedback, энергии и нормы. Контрасты reset−live, reader−live,
reader(K_after)−reader(K_initial) парные по seed×map; двухфакторный bootstrap
5000 реплик. 999 map-grouped permutations проверяют ассоциацию frozen reader на holdout.
Это не 192 независимых trials: независимые уровни панели — 4 seeds и 8 mappings.
При таких размерах интервалы приближённые. Все контрасты публикуются, знак не отбирается.

Неудача внешнего линейного reader не доказывает отсутствие информации в K.
Хорошее внешнее чтение при плохом native — свидетельство ограничений доступного
считывания, а не специфической полезности A. Преимущество reset при той же K указывает
на зависимость доступа от состояния. Для разрешения дальнейшей длительной жизни
нужна accuracy не ниже 75% именно при CARRY, а затем отдельная проверка удержания
и joint learnability. Этот порог не превращает короткий опыт в доказательство LIFE.

## Воспроизводимость

Сохраняются все события, полные checkpoints и stream schedule/RNG/cursor,
features, predictions, model coefficients, immutable plan/source hashes и статусы.
Смена исходников после фиксации плана отклоняется. Восстановление продолжает из
последнего checkpoint, не пересчитывает уже завершённые жизни и не перенастраивает
замороженный reader. Ошибка жизни прекращает зависимый анализ, данные не исключаются
молча. Максимум два вычислительных worker, BLAS threads=1. Научный run ограничен
двумя часами wall на invocation; budget/error фиксируются в STATUS.

Команды из worktree:

```powershell
python -m pqt_qcat.memory.codex_memory_location init --output C:\AGI\PQT_QCAT_AUDIT\NEW_RUN
python -m pqt_qcat.memory.codex_memory_location run --output C:\AGI\PQT_QCAT_AUDIT\NEW_RUN --workers 2
```

Повтор `run` на том же неизменном каталоге — resume. Повтор на новой папке с тем
же планом — воспроизведение уже известной панели, не новая независимая конфирмация.

## Инженерные изменения

- Checkpoint v2: атомарная NPZ без pickle, generic nested state; дополнительные
  readout наследника и физические параметры не теряются. Несовместимый тип ядра
  или strict config отвергается, включая substeps. Non-strict restore пересоздаёт
  зависимые объекты интегратора. Старые неполные snapshots требуют исторического runner.
- Сохраняется runner state, включая cursor/RNG и pending feedback; есть тест нового
  процесса и ненулевой eligibility trace. В stochastic step передаётся RNG ядра.
- Фактическое и предложенное ΔK разделены. Исторический direct-head baseline
  сохраняет frozen K; вариант с пластичной K включается отдельным явным параметром.
- Энергия — сумма существующих шести cell potentials. Это диагностическая сумма,
  не доказанный Lyapunov functional связанной системы. Ошибка не заменяется нулём.
- Нормы/энергии отслеживаются после каждого внешнего подшага; внутренние adaptive
  trial states в этот максимум не включены. Основной опыт использует fixed Heun.
