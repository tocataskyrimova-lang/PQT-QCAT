## Stage 0 и происхождение исходников

Заархивированы Git-дерево базы, точный исходный код эксперимента и входной ZIP.
Хеш ZIP — `e1a168264c942d1ac717734b9446f13979c3f46200bcfe3406747e86f52290d2`.
Научный код MEMORY-LOCATION-001 относится к `9cb2ddae3ff130caab9bfca6a5c2bebb51501224`.
В последующем коммите базы менялись вспомогательная диагностика, отчётность и тест
манифеста. Совместимость проверили по результату вычислений. Для B0 и RESET на одной
сохранённой жизни каждого режима побитово совпали все 72 вектора логитов, конечные K/Z
и логиты обоих штатных контрольных способов чтения.

Прошли 26 целевых тестов, включая существующие регрессии MEMORY-LOCATION-001. В тесте
с ненулевым шумом реальные и теневые ветви потребляют одинаковые шумовые последовательности.
Парные нулевые входы дали ровно нулевой событийный признак. Нарушения порядка обратной
связи и входы из тестовых источников отвергаются на границе интерфейса. NPZ-проверка
охватила снимок с ожидающей обратной связью. Отдельный процесс возобновил B3
после 24-го события. Все 72 записи и поля снимка после 72-го события совпали точно.

На Stage 0 выполнено 40 жизней. Один запрос получает одну из четырёх меток, равномерно
распределённых между жизнями. Средняя точность последних восьми событий приведена
ниже. В скобках — показатели по двум seeds.

|---:|---:|---:|---:|---:|
| 98,44% (100 / 96,88) | 73,44% (87,50 / 59,38) | 93,75% (100 / 87,50) | 75,00% (87,50 / 62,50) | 98,44% (100 / 96,88) |

Порог 50% на каждом seed прошли все четыре CARRY-плеча. Предсказание одного заранее

при хорошей точности. Нулевая выборка для вывода о значимости из неё не строилась.

## Что изменилось в пластичности

| Плечо | Средняя норма применённого ΔK | Средняя норма K₇₂ − K₀ | Средний максимум нормы Z |
|---|---:|---:|---:|
| B0 | 2,2418 | 38,59 | 15,36 |
| B1 | 0,0763 | 2,47 | 15,06 |
| B2 | 2,7377 | 13,37 | 14,88 |
| B3 | 0,1005 | 3,21 | 15,03 |
| B0 с ограничением нормы | 0,3736 | 8,70 | 15,26 |
| RESET | 0,2987 | 8,64 | 2,49 |

1. **Q вычитает устойчивый фон.** Во всех CARRY-плечах средняя норма legacy-признака
   около 4,0–4,2, событийного — около 0,116. В последних 24 событиях B1 в E1
   сосредоточено 99,94% квадрата нормы событийного признака против 20,48% legacy.
   Разность средних косинусных сходств «одинаковые query» и «разные query» у B1
   составила +1,015 для событийного признака и −0,033 для legacy.
   Признак распознаёт идентичность физического входа. Этого оказалось недостаточно
   для выбора правильного класса штатной траекторией.
2. **Q одновременно ослабляет запись.** При той же eta B1 уменьшает средний шаг K
   примерно в 29 раз. Прямой контроль B0 с потолком 0,375886, взятым по максимальному
   шагу B1 на development, даёт более высокую точность и хуже NLL.
   Средний шаг у этого контроля всё ещё примерно в пять раз крупнее, чем у B1.
   Опыт разделяет смену признака и введение потолка, а эффект полной нормализации
   масштаба с сохранением направления остаётся неопределённым.
3. **Вероятности улучшились без роста accuracy.** При target-only Q уменьшает NLL
   на 0,119 [−0,200; −0,044]. При полной ошибке уменьшение относительно B2 равно
   0,087 [−0,156; −0,023]. Это улучшение вероятности назначенной метке на панели.
   Оно совместимо с более мягкими логитами и само по себе не доказывает
   калибровку уверенности или функциональное освоение.
4. **В K появляется диагностический след.** Декодер K_initial дал 25,00% для
   каждого режима. Его аналог K_after дал 28,70% для B0, 51,85% для B1,
   28,70% для B2, 57,41% для B3, 32,41% для B0 с ограничением нормы и 53,70%
   для RESET. Cross-fit исключает и seed, и mapping оцениваемого примера из fit.
   Покрытие истинных классов в обучающих folds — 77,78%. Для B1/B3 средняя
   описательная точность по перемешанным mappings — 37,39%/36,66%.
   Folds перекрываются, поэтому этот контроль не трактуется как p-value.
   Диагностика совместима с записью более различимого следа и слабым доступом
   штатного считывателя. Для причинной проверки использования следа нужно
   отдельно вмешаться в K при фиксированном Z.

## Равный бюджет, непрерывность и границы вывода

За два этапа завершены 148 жизней и 8 736 событий без численных отказов.
Сохранено 512 исходных именованных checkpoints. На Stage 1 каждое плечо
выполнило ровно 1 152 живых подшага, 1 152 теневых, 1 408 контрольных
и 72 вычисления обновления на жизнь. Полный CPU по задачам-жизням — около
1 066 секунд без учёта preflight, сводного анализа и упаковки.
У всех CARRY-плеч Stage 1 проверены 6 390 точных стыков Z между событиями.
Верификатор пересобрал K из записанных признаков и ошибок, проверил
равенство парных событий, RNG, начальных K/B/W, неизменность B/W,
предсказательные журналы и совпадение K_proposed/K_post с контрольными суммами.

Удержание здесь означает считывание одного правила после паузы.
Переключение на новое правило и интерференция старого с новым оставлены
для отдельного протокола. N/F представлены типом наблюдённого свидетельства,
реестром и синтетическими проверками правил принятия. В экспериментальных
плечах принятие выполняется для любой валидной обратной связи.
Пакет содержит только Stage 0 и Stage 1 development. Ни финальная панель,
ни M5, ни DREAM, ни Stage 2 не выполнялись.

## Артефакты и воспроизведение

Каталог прогона в worktree — `results/exploratory/LIFE_QNUF_001/RUN_001`.
Машинные результаты — `stage0/controls.json`, `stage1/contrasts.json`,
`stage1/per_life.csv`, `verification.json`. Каждая жизнь содержит отдельный
журнал до обратной связи, полные записи, snapshots и ресурсные показатели.
`frozen_config.json`, `source.json`, `preflight/PASS.json` и SHA256-манифест
позволяют проверить соответствие данных зафиксированному эксперименту.

Из worktree можно повторить проверку уже сохранённых данных и возобновление
в новом каталоге. Команда `run` на комплекте frozen config, source hash
и preflight проверяет код и использует завершённые жизни из этого каталога.
Повтор тех же seeds и mappings остаётся репликацией development.

```powershell
python scripts/verify_qnuf_run.py results/exploratory/LIFE_QNUF_001/RUN_001
python scripts/replay_qnuf_checkpoint.py results/exploratory/LIFE_QNUF_001/RUN_001 results/exploratory/LIFE_QNUF_001/REPLAY_NEW
```
