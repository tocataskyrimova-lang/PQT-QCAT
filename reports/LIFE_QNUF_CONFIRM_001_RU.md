## Изменения K и качество собственного CARRY

В среде без повторов средняя NLL внешнего ответа снизилась с 0,934 у raw MM
до 0,658 у raw SS. Парная разность −0,276 [−0,308; −0,226]. Точность
последних восьми действий выросла с 85,00% до 92,92%. У таблицы после общего
префикса NLL 0,001006 по фиксированному выбору амплитуды логитов.

Средняя норма одного фактического шага ΔK выросла с 0,059 у raw MM до 0,584
у raw SS. Конечное расстояние от K на старте эпизода — 0,796 и 6,968
соответственно. У двух нормированных политик средняя норма шага равна 0,50.
Эти показатели измерены на собственной траектории каждого режима.

На общей фиксированной пробе из живого Z после среды без повторов CARRY
достиг 30,56% при raw MM и 32,22% при raw SS. Разность +1,67 п.п.
[−1,11; +6,67]. NLL собственной пробы выросла на 0,451 [+0,112; +0,916].
На фактических траекториях внутренние предсказания дали 32,64% и 32,50%.
Подтверждённое улучшение относится к внешним действиям Z0-64. Собственный
доступ к памяти из непрерывного Z остаётся слабым.

## Инженерный вердикт `CONFIRM_VALID`

Проверены 420 полных жизней, 10 080 действий после префикса и все 1 440
записей предварительного опыта. Таблица дала 24/24 в 60/60 жизнях. По байтам
квитанций проверены фиксация действия до реакции и отсутствие метки в
предварительном пакете. Анализатор пересчитал реакцию среды, фактические
ΔK, источники логитов и eligibility, непрерывность Z/RNG и равенство B/W.
В каждой паре нейронных политик с собственной K первое действие совпало. Для всех 14
условий первого блока проверено возобновление после durable action в возрасте
12. Совпали 12 оставшихся записей действий, реакции и конечные снимки. Пройдены
5 целевых тестов. Предупреждение `pynvml` касалось устаревшей зависимости.

Четыре фазы заняли 30,91 мин при шести воркерах с одним BLAS-потоком.
Во всех нейронных условиях — 288 физических подшагов и одна запись K за
событие. Основные и донорские жизни использовали 2 488 320 подшагов, общие
префиксы 46 080. Пробы и точные продолжения учитываются отдельно. Без
повторов среднее измеренное время нейронного события составляло примерно
1,18–1,20 с, табличного — 0,66 мс, включая журналирование и конкуренцию
воркеров. Табличный контроль не выполнял нейронные подшаги.

Подтверждение ограничено одним правилом и 24 действиями после общего опыта.
Проект проверки двух конфликтующих правил и удержания вынесен в
`LIFE_QNUF_TWO_RULE_PROPOSAL_RU.md`. Эксперимент по нему не запускался.

## Независимая панель и исходная реализация

Исходная поставка B2A-CAUSAL `01fa3ae7847f7e5bf8c0397702bf31f386d73690` принята
как `CAUSAL_VALID` / `DEVELOPMENT_CAUSAL_EVIDENCE`. Её исполняемая версия
`ec0203161c92db45356b6cc32051d99990a2b4a8`, SHA-256 исходного ZIP
`358ba2e09c0db539ac851847bcbd8f92ed424edcefb2a5d9a83eccccb47f4975`.
Проверены все 1 512 файлов старого манифеста. Неизменённый архив вложен в
поставку подтверждения. Исполняемая версия подтверждения —
`43297fce8d24eb783c0cb10d38fbb9662b872a02`. SHA коммита поставки указан в
`DELIVERY.json`.

Панель из 30 блоков полностью пересекает пять новых core-seeds 931731–931735
и шесть новых mappings. Они отличны от 6 прежних LIFE-QNUF mappings и 24
MEMORY-LOCATION mappings. Новые правила, 48 предварительных запросов, первый
запрос 49, 24 внешних смещения и статистика имеют отдельные RNG-ключи.
`LOCK.json` фиксирует SHA-256 `PLAN.json` и `SOURCE.json` перед `prepare`.
Ни физика B3, ни правило записи из B2A-CAUSAL не изменены.

Для каждого блока все политики и таблица получают одни и те же 48 наблюдений
до основного эпизода. Каждый из шести токенов встречается восемь раз.
Нейронные политики стартуют из одного checkpoint, таблица — из состояния,
восстановленного из тех же 48 свидетельств. В дальнейшем в каждом событии
действие записывается до реакции среды и раскрытия метки. Во всех нейронных
плечах внешнее действие выбирает Z0-64. MM, SM, SS обозначают источники
логитов и eligibility для записи, а `norm 0,50` — фиксированную норму ΔK.
Траектории среды могут разойтись после различных действий. Смещения по
возрасту эпизода общие для пар. Порог установлен для одной конкретной пары
raw SS минус raw MM в advance. Остальные плечи сохранены в заданном порядке,
их сравнения описательные.

В каждой жизни 24 действия. Вердикты используют парные разности средних по
блокам. 95%-интервалы построены 10 000 перекрёстными bootstrap-репликами с
независимым ресэмплированием пятью seed и шестью mappings. Число действий
не используется как число независимых наблюдений. Критерий точности требует
среднюю прибавку ≥5 п.п. и нижнюю границу ДИ >0. Критерий награды требует
среднюю прибавку ≥+2 и нижнюю границу ДИ >0. Зарегистрированный блок не
заменяется при сбое. Табличный контроль служит проверкой разрешимости после
равного опыта. Оценка его NLL использует фиксированный логит 8 для запомненной
метки и нулевые логиты остальным.

## Воспроизведение и артефакты

В архиве — замороженный план, оба исходных Git SHA, Git bundle,
оригинальная поставка B2A-CAUSAL, снимки prefix / pending / end, все
действия, реакции, метки и обновления, точные продолжения, массивы доноров,
машинные метрики и SHA-256. `per_event.csv` и `per_life.csv` представляют все
проверенные события и жизни. Сырые журналы содержат логиты и хеши состояния.

Из `CONFIRM_SOURCE.bundle` клонировать ветку `exp/life-qnuf-confirm-001`.
Для нового прогона извлечь вложенный `B2A_CAUSAL_ORIGINAL.zip` в папку
`$reference`. `$archive` указывает на вложенный ZIP, `$oldMemory` — на копию
`PREVIOUS_MEMORY_PLAN.json`, `$run` — на новую папку.

```powershell
git clone --branch exp/life-qnuf-confirm-001 C:\path\CONFIRM_SOURCE.bundle C:\path\confirm-source
Set-Location C:\path\confirm-source
python -m pqt_qcat.memory.qnuf_confirm init --output $run --reference $reference --archive $archive --old-memory $oldMemory
python -m pytest pqt_qcat/tests/test_sidecar_causal.py pqt_qcat/tests/test_sidecar_b2a.py -q
foreach ($phase in ('prepare','primary','controls','resume')) {
    python -m pqt_qcat.memory.qnuf_confirm $phase --output $run
    if ($LASTEXITCODE -ne 0) { throw "Failed phase $phase" }
}
python scripts/analyze_qnuf_confirm.py $run
python scripts/plot_qnuf_confirm.py $run
```

Версии Python и библиотек указаны в `SOURCE.json`. Локальный путь до базового
архива является частью хеша плана. Замена пути в новом прогоне даёт другой
хеш при одинаковой регистрации условий. Для независимой проверки уже
сохранённой поставки без изменения артефактов выполнить из клона bundle:

```powershell
python scripts/analyze_qnuf_confirm.py $archivedRun --verify-only
```
