# LIFE-ACCESS-STATE-001 · Functional Sidecar B0/B1

**Инженерный вердикт — `B1_VALID`. Научный вердикт — `B1_DEPLOYED_SIGNAL`
на использованной development-панели.** Sidecar-Z0-64 поднял точность
выданного ответа с 30,32% у равного по бюджету живого Sidecar до 75,69%.
Основной обучающий поток сохранил 32,18% и воспроизведён побитово.

## Источники и B0

Рабочая ветка — `exp/life-functional-sidecar-b1`. База Stage A —
`c32e8892f4aa5a37c659b89e23c58eefe09ae024`. Проверены 1 270 записей
манифеста Stage A, хеши исходников в его `FROZEN_CODE.zip`, версии зависимостей
и все исторические файлы, использованные в B0/B1. Бриф из переданного ZIP
сохранён с исходным SHA-256. Исторический протокол и операторы ядра унаследованы
без изменения. Единственная начальная попытка инициализации остановилась
до фиксации плана из-за неверного импорта защиты seeds. Импорт исправлен
до измерений, рабочий прогон проведён в каталоге RUN_002.
Коммит вычислений — `9885a3c4276b628dedc7b8a352f4a11ef4b77a0d`.

Прошли **14 целевых тестов B0**. Проверены запрет feedback без подтверждённого
действия, отказ при изменении байтов действия, разделение внешнего ответа и
обучающего прогноза, атомарный checkpoint в ожидающей feedback фазе, правильное
Z0, парный RNG, изоляция с включённым шумом в тесте, донорская матрица и бюджет.
Основные измерения используют неизменённый физический режим из Stage A.

По всем 18 историческим блокам побитово совпали 36 опорных векторов логитов
на событии 49. B3 Sidecar-Z0-64 воспроизвёл **14/18**, Sidecar-LIVE-64 —
**4/18**. Это проверка источника и реализаций до последовательного прогона.

## Что именно измерено

Каждый из шести режимов начинает с собственного точного клона checkpoint 48
и проходит события 49–72. На каждое событие среда сначала передаёт запрос.
Точная копия стартового состояния служит источником для Sidecar. Наш журнал
сохраняет оба вектора логитов и внешнее действие с принудительной записью на
диск. Затем среда принимает этот ответ, вычисляет фактическую награду
и раскрывает метку. Она возвращает одну и ту же метку при разных действиях.
Следующий запрос также общий. Main использует собственный прогноз, своё
eligibility и полученную метку. Sidecar получает временную копию ядра без
обратной записи K, Z, eligibility, pending и RNG.

Математический тест H_B1 сравнивает число верных внешних ответов
S-Z0-64 и S-LIVE64 в каждом из 18 блоков. Оба режима получают одинаковые
64 такта побочного чтения при общем начале и общей K. Для SELECTIVITY
сравниваются начальная K и K другого mapping того же seed и pre-event возраста.
Чужая матрица восстанавливалась из архивного checkpoint и верифицированных по
хешу приращений для каждого события. B/W, A и интегратор сверены.
Правило выбора чужого mapping фиксировано заранее. Сами targets и mapping ID
не маршрутизируются в предсказатель; режим запроса содержит только наблюдение.

План фиксирует условие **B1_DEPLOYED_SIGNAL**. Нужны не менее +10 п.п. над
живым 64-тактовым Sidecar с нижней границей парного 95%-го интервала выше 0.
Кроме того, нужно преимущество не менее +10 п.п. над каждым донорским контролем.
Интервалы рассчитаны по 5 000 репликам двухфакторного парного bootstrap с
пересэмплированием seeds и mappings. Запросы внутри одного блока вместе
составляют одно наблюдение. Выборка development содержит три seeds и уже
использовалась в прежних стадиях.

Выигрыш S-Z0-64 над S-LIVE64 составляет 196 дополнительных верных ответов
и **+45,37 п.п.** на всей серии с приближённым 95%-м ДИ **[31,71; 56,94]**.
Разности по трём seeds составили +47,22, +53,47 и +35,42 п.п.
По отношению к обычному CARRY получено +43,52 п.п. [31,25; 51,62].
Короткий S-Z0-8 получает 147 ответов, поэтому
условия чтения влияют и через начальное состояние копии, и через горизонт.
На длинном горизонте замена своей K на начальную снижает точность на
50,69 п.п. [41,67; 58,33], а замена на K другого mapping — на 53,47
п.п. [42,13; 65,28]. Оба донорских сравнения проходят заданный порог.
NLL внешнего ответа равна 0,939 у S-Z0-64, 1,705 у S-LIVE64,
1,462 с начальной K и 1,577 с чужой K. Средний signed margin у S-Z0-64
равен +0,399 против −0,688 у S-LIVE64. Помоментная точность, матрицы
ошибок, ДИ и контрасты по всем метрикам сохранены в артефактах.

## Непрерывность и предел вывода

Независимая сверка проверила **2 592 записи** подтверждённых действий,
432 канонических предсобытийных снимка и **108 основных жизней**.
Все ответы были зафиксированы раньше раскрытия метки. У каждой жизни
с исходными записями совпали логиты main, обновления K и конечный снимок.
Защита сравнивает полное ожидающее feedback состояние до и после чтения
Sidecar. Ошибок численной интеграции в панели нет.

Для заранее выбранного первого блока шесть режимов возобновлены отдельно
из закрытого checkpoint после события 56 и из снимка события 57 после
выдачи действия, пока метка ещё ожидается. Первый вариант пересчитывает
весь хвост, второй восстанавливает подтверждённое действие по байтам журнала.
Во всех **12** проверках состоялось точное продолжение **16** событий.
Пакеты прогнозов, награды, метки, обновления и конечные NPZ-данные совпали.
Хронометрические поля при сравнении результатов replay исключались.

Accuracy основного прогнозиста — **139/432 (32,18%)**, NLL — **1,641**
во всех режимах. Внешнее действие влияет на полученную награду,
а метка и будущий вход остаются общими. B3 поэтому получает те же
обучающие данные и делает те же обновления. Слабое чтение и освоение
правила в живом CARRY остаются нерешёнными. Совместное удержание двух
правил и поведение при зависимости следующего наблюдения от выданного
действия лежат за пределами этой панели. Текущий результат удовлетворяет
критериям для отдельного обсуждения B2. Поставка заканчивается Stage B1.

## Воспроизведение

Запуск использует обычный интерпретатор Python с включёнными проверками.
Исходники, проверенные снимки, исходные журналы и манифесты находятся в
комплекте поставки. Для переноса распаковать `SOURCE_QNUF.zip` и
`SOURCE_STAGE_A.zip`, затем указать корень QNUF и внутренний каталог
`RUN_001` поставки Stage A. Результаты измерений воспроизводить в новом каталоге.
Эти команды повторяют прежнюю development-панель.

```powershell
$history = 'C:\AGI\PQT_QCAT_AUDIT\PQT_QCat_QNUF_001\results\exploratory\LIFE_QNUF_001\RUN_001'
$stageA = 'C:\AGI\PQT_QCAT_AUDIT\LIFE_ACCESS_STATE_RUN_001'
$brief = 'C:\Users\RandomX77\Downloads\Stage_B_Codex_Brief.zip'
$out = 'C:\AGI\PQT_QCAT_AUDIT\FUNCTIONAL_SIDECAR_REPLAY'
python -m pqt_qcat.memory.functional_sidecar init --output $out --history $history --stage-a $stageA --brief $brief
$env:LIFE_SIDECAR_TEST_RUN = $out
python -m pytest pqt_qcat/tests/test_functional_sidecar.py -q -p no:cacheprovider --junitxml="$out\B0_TESTS.xml"
python -m pqt_qcat.memory.functional_sidecar preflight --output $out
python -m pqt_qcat.memory.functional_sidecar run --output $out --workers 2
python -m pqt_qcat.memory.functional_sidecar resume-test --output $out
python scripts/analyze_functional_sidecar.py $out
python scripts/plot_functional_sidecar.py $out
```
