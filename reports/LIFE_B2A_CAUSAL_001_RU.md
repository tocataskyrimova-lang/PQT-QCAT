# LIFE-B2A-CAUSAL-001

## Научный вердикт на development

**Вклад событийного признака, логитов и масштаба зависит от их сочетания.**
В исходном B3 наиболее крупный эффект дала замена eligibility. Замена
логитов повысила точность при признаке Sidecar. Согласованная норма
подтвердила вклад направления записи и выявила взаимодействие с её масштабом.
При 0,50 логиты Sidecar дали 87,85% даже в сочетании с eligibility MAIN.
Преимущество SS над MM сильно увеличивалось в среде, повторяющей ошибки.

### 1. Событийный eligibility Sidecar

**Причинный вклад при исходном B3 и вклад направления при равной норме.**
С исходной записью замена признака при logits MAIN (MS–MM) дала +52,43 п.п.
(95% ДИ [+25,00; +71,88]) и +26,25 награды. При logits Sidecar (SS–SM)
разность составила +70,49 п.п. [+47,57; +82,29]. Часть эффекта может идти
через размер записи. Средние фактические нормы шага у raw MM, SM, MS, SS
равны 0,0199, 0,0155, 0,8906 и 0,5549. Последние два плеча существенно
сильнее меняли K, при этом raw MS делало больший шаг, чем raw SS.

Выигрыш от eligibility сохранился при одинаковой длине обновления, но
зависел от источника ошибки. При норме 0,05 и logits Sidecar (SS–SM)
он составил **+39,58 п.п.** [+19,43; +56,25]. При 0,50 и logits MAIN
(MS–MM) он составил **+21,18 п.п.** [+4,17; +49,31]. При 0,50 и logits
Sidecar разность была +3,13 п.п. [−2,08; +12,50]. Последний интервал
оставляет неопределённым дополнительный вклад eligibility в этом режиме.

### 2. Логиты Sidecar в ошибке записи

**Причинный вклад при условии, что направление и масштаб записи достаточны.**
С исходным eligibility MAIN замена логитов изменила точность на −0,35 п.п.
[−1,39; 0,00]. Весь интервал лежит внутри порога ±5 п.п. При eligibility
Sidecar замена логитов добавила **+17,71 п.п.** [+4,17; +34,03] и +7,65
награды. Взаимодействие двух факторов составило +18,06 п.п. [+4,17; +34,03],
так что вклад нельзя однозначно поделить на две аддитивные доли.

При одинаковой норме 0,05 и eligibility Sidecar выигрыш от логитов составил
**+28,47 п.п.** [+4,17; +51,39]. При 0,50 и eligibility MAIN он составил
**+35,76 п.п.** [+1,39; +63,19]. Знак взаимодействия при 0,50 сменился
(−18,06 п.п. [−47,92; −1,04]). Это вмешательство проверяет логиты как
источник ошибки записи. Во всех плечах действие по-прежнему выдаёт Z0-64.

### 3. Величина обновления K

**Причинный вклад масштаба поддержан при фиксированном выборе источников.**
При увеличении общей нормы с 0,05 до 0,50 точность выросла на +58,68 п.п.
[+29,17; +83,33] у SM, +32,99 п.п. [+13,19; +56,94] у MS и +22,22 п.п.
[+5,21; +42,71] у SS. У MM оценка +31,25 п.п. [0,00; +68,40] не прошла
критерий положительного эффекта. Во всех событиях нормированных плеч
фактическая норма равна назначенной с допуском `2e-14`, нулевых
кандидатов не было.

Масштаб сам по себе не объясняет исходный результат: при фиксированной норме
0,50 разность SS–MM осталась +38,89 п.п. [+6,94; +64,58]. Размер конечного
смещения K также не равен пути обновлений. Например, в исходном SS средний
шаг 0,555 за 24 события дал среднее конечное расстояние 6,60 от K на старте.

### 4. Роль среды и собственный CARRY

Без повторов итоговый контраст SS–MM составил **+6,60 п.п.** [+1,39; +14,58]
по точности и **+1,979** [+0,375; +4,458] по награде. По точности он проходит
заданный порог, по награде его средняя оценка ниже порога +2. Падение
контраста между двумя средами — 63,54 п.п. [43,75; 76,04]. Точность самого SS
почти сохранилась (89,93% → 88,89%). Базовое MM получило больше разных
запросов (3,58 → 5,92), а максимальная серия его ошибок сократилась в среднем
с 19,08 до 1,17. Большой относительный выигрыш B2A в значительной мере
связан с выходом из петли повторов. Результат относится к двум проверенным
правилам перехода среды.

В исходном SS точность последних восьми действий — 96,88%, NLL выданных
ответов — 0,665. У MM — 9,38% и 1,197. Эти операционные метрики рассчитаны
на запросах, которые посетила сама политика. Для CARRY на общей фиксированной
пробе после жизни получено 30,56% у raw MM, 25,00% у raw MS и 37,50% у raw
SS. NLL этой пробы у raw SS составляет 2,133 против 1,826 у raw MM. Внешний
выигрыш сопровождается слабым доступом владельца памяти из живого Z.

### 5. Отрицательные контроли согласованного обновления

| K внешней ветви при SS | Точность | Награда | NLL | Средняя норма ΔK в main |
|---|---:|---:|---:|---:|
| Своя обученная | 89,93% | +20,90 | 0,665 | 0,555 |
| Начальная | 2,43% | −21,33 | 1,642 | 0,640 |
| Обученная на чужом mapping | 2,78% | −20,77 | 2,591 | 1,083 |

Парное преимущество собственной K составило +87,50 п.п. [+83,33; +90,97]
над начальной и +87,15 п.п. [+80,56; +91,67] над чужой матрицей. У обоих
доноров точность последних восьми действий равна 0%. Подмены меняют внешнее
чтение и связанные с ним логиты и eligibility. Обновления сохраняются в
собственной K main, тогда как внешний считыватель продолжает брать донорскую
матрицу. Поэтому этот контроль проверяет необходимость доступа к своей
накопленной K для текущей политики SS. Он не измеряет скорость переучивания
донорской K при разрешённой записи в неё.

### 6. Одношаговое вмешательство из одного состояния

Для 36 pending-снимков сохранены 540 вариантов чтения. Прогноз, уже
выданное действие, фактическое свидетельство и следующий запрос одинаковы
во всех копиях данного снимка. Только 23 снимка имеют следующий запрос,
отличающийся от текущего. В статистике сначала усредняются снимки внутри
блока, затем блоки. Следующий запрос оценивается только по этим 23 снимкам.

- На уже предъявленном запросе NLL без новой записи — 0,918, после одной
  записи raw SS — 0,725. Парная разность −0,193 [−0,266; −0,150]. На другом
  следующем запросе разность +0,020 [−0,002; +0,058]. Локальная коррекция
  подтверждена. Польза на другом токене после одной записи остаётся
  неопределённой.
- Для того же направления SS переход от 0,05 к 0,50 снижает текущую NLL
  на 0,145 [0,124; 0,171]. Разность на другом следующем запросе составляет
  +0,011 [−0,002; +0,028]. Масштаб даёт непосредственный эффект на только
  что подкреплённом запросе. Траекторные выигрыши измеряются отдельно.
- Средний косинус между ΔK и кандидатом MM в том же снимке — 0,834 для SM,
  0,440 для MS и 0,401 для SS. Косинус каждого нормированного кандидата с
  собственным raw-направлением равен 1 в пределах численной точности.
- Без какой-либо новой записи подстановка начальной K увеличила NLL
  текущего запроса на 0,485 [+0,351; +0,615], подстановка чужой K — на
  0,705 [+0,100; +1,271]. Эта проверка фиксирует состояние и запрос и
  подтверждает прямой вклад доступной K в штатное чтение Z0-64.

## Дизайн

Цель — разделить роль логитов в ошибке записи, событийного eligibility и
фробениусовой нормы фактического ΔK. В каждой жизни решение принимает Z0-64.
Слова `MAIN` и `SIDECAR` относятся к тому, откуда правило обновления берёт
логиты и eligibility. В `SM` логиты берутся из Sidecar, а eligibility — из
main. В `MS` источники поменяны местами. `MM` и `SS` соответствуют крайним
политикам B2A. На одном событии каждая политика рассчитывает одни и те же две
пары физических траекторий query/no-input. Сложность 288 подшагов на событие и
6 912 на жизнь, плюс 192 подшага на фиксированные пробы после эпизода. Время
измерено отдельно, затраты на подготовку checkpoint и журналирование входят
в него. На награду влияет действие, предъявленный запрос и серия ошибок.

Начальные checkpoint после 48 событий, 12 блоков, 24 события и внешний поток
смещений взяты из B2A. Полный SHA поставки B2A —
`16c75c1f43ffc46b3f3277f8f45c8b5d047bfd74`, SHA-256 исходного ZIP —
`8366272bc8459f0bf9a4f7c9b934ebabdb88e3aafc7ec948ea83f1cbd3aa09c2`.
Сверены все 1 540 файлов исходной поставки. Исполняемый коммит эксперимента —
`ec0203161c92db45356b6cc32051d99990a2b4a8`. Коммит поставки указан в
`DELIVERY.json`. 48D-ядро, K исходного состояния, A, B/W и интегратор
унаследованы из B2A. Новые инициализации, финальные панели, DREAM, N/F и
переход к нескольким правилам не запускались.

Режим `raw` использует исходный B3 с покоординатным clipping. Для равной
нормы предварительно зафиксированы 0,05 и 0,50. В этих режимах сохранено
направление после clipping, а величина доведена до общего значения. Оба
значения заданы независимо от результатов и меток. Для точного нуля
сохраняется ноль. При отсутствии нулей условие равного масштаба действует
на каждом событии каждого плеча, включая разошедшиеся траектории.

Для каждого выбранного прогноза ошибка \(e\) строится из softmax по четырём
классам и подтверждённой метки. Событийный признак \(\phi\) равен
разности \(\tanh Z\) между парными траекториями с запросом и без запроса.
Кандидат B3 — \(\operatorname{clip}(\eta(W^\mathsf{T}e)\otimes\phi)\).
Равная норма меняет только длину этого кандидата. При одношаговой проверке
веса, полученные после единственного обновления, оцениваются на одной
замороженной паре запросов из того же состояния. Следующий запрос
анализируется отдельно, когда отличается от предъявленного.

В `advance` обе реакции ведут к новому запросу, но их смещения различаются.
Награда и штраф за серию ошибок сохранены. Это связывает действия с опытом,
одновременно убирая повтор запроса после ошибки. В донорских жизнях
использована начальная K или K из raw/SS соседнего mapping того же seed на
том же возрасте. Подмена касается внешнего чтения и его парного признака.
Своя K main продолжает меняться после обратной связи.

Пары блокированы по исходным seed и mapping. Средние эффекты, простые
контрасты и взаимодействия рассчитаны по парным разностям. Исследовательские
95%-интервалы используют 5 000 реплик с отдельным ресэмплированием трёх seed
и четырёх mapping. Критерий практического сигнала был зафиксирован до запуска
как средняя разница ≥5 п.п. по точности, либо ≥2 по награде, и нижняя граница
ДИ >0 для соответствующего показателя.

## Инженерный вердикт `CAUSAL_VALID`

- Проверены журналы 216 жизней и 5 184 события. Байты записи действия, её
  квитанция, реакция, раскрытая метка и запись идут в заданной последовательности.
  Пересчитаны переходы среды, условие равенства стартового состояния и все ΔK,
  включая ошибки из указанного источника и признаки из парных траекторий.
  Подтверждены цепочки Z, RNG и полных состояний. B/W и параметры физики
  совпадают со стартовым checkpoint. Для всех плеч с собственной K первое
  действие побитово совпадает, поскольку различия записи начинаются позже.
- Для 24 исторических жизней raw MM и raw SS повторены действия, обновления
  и хеши состояния на всех событиях B2A. Все 18 условий первого блока точно
  продолжились из pending checkpoint возраста 12. В каждом случае совпали
  оставшиеся 12 событий, байты журнала и конечный снимок. Эти возобновления
  проверяют каждую политику на её собственной траектории.
- 5 целевых тестов прошли. Одно предупреждение относится к устаревшему
  `pynvml`. Четыре вычислительные фазы заняли 19,07 мин на шести воркерах
  с одним BLAS-потоком. Основные 216 жизней израсходовали 1 492 992 физических
  подшага на действия и обновления и 41 472 на фиксированные пробы. Для
  16 факторных условий измеренное среднее время события лежало в диапазоне
  1,102–1,116 с при параллельном исполнении. Одношаговые копии и продолжения
  учитываются отдельно в исходных журналах.

В опыте фиксированы один mapping на жизнь, короткий горизонт и только
историческая development-панель. Результат поддерживает конкретные
механизмы записи для наблюдаемой задачи. Перенос на новые mapping, более
долгий горизонт или конфликт правил остаётся за пределами этой проверки.

## Воспроизведение

Полный архив содержит журналы, начальные источники, snapshots pending и end,
копии продолжений, матрицы доноров, матрицы ΔK одношаговых вмешательств,
CSV, анализ и `CAUSAL_SOURCE.bundle`. Вложенный `B2A_ORIGINAL.zip` — исходная
поставка без изменения байтов. Распаковать её в `$reference` и распаковать
из неё `INPUT_QNUF.zip` в `$qnuf`, `INPUT_B1.zip` в `$b1`.

```powershell
git clone --branch exp/life-b2a-causal-001 C:\path\CAUSAL_SOURCE.bundle C:\path\causal-source
Set-Location C:\path\causal-source
python -m pqt_qcat.memory.sidecar_causal init --output $run --reference $reference --archive $archive --history $qnuf --b1 $b1
python -m pytest pqt_qcat/tests/test_sidecar_causal.py pqt_qcat/tests/test_sidecar_b2a.py -q
foreach ($phase in ('primary','controls','one-step','resume')) {
    python -m pqt_qcat.memory.sidecar_causal $phase --output $run
    if ($LASTEXITCODE -ne 0) { throw "Failed phase $phase" }
}
python scripts/analyze_sidecar_causal.py $run
python scripts/plot_sidecar_causal.py $run
```

`$archive` — путь к вложенному `B2A_ORIGINAL.zip`, `$run` — новая папка.
Версии Python, NumPy, SciPy, Torch и Scikit-learn сохранены в `SOURCE.json`.
Путь участвует в SHA плана, поэтому пересозданный план в другом каталоге
получит собственный SHA. Экзогенный поток и экспериментальная панель при
этом совпадают. Для сверки уже сохранённой поставки без изменения файлов
запустить из клона поставки:

```powershell
python scripts/analyze_sidecar_causal.py $archivedRun --reference $reference --history $qnuf --b1 $b1 --verify-only
```
