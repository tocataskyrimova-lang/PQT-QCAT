# LIFE-QNUF-CONTEXT-BIND-001 · D4

## Научный итог

**Защита A за счёт направления — `UNDECIDED`. Вклад масштаба подтверждён.**
При одинаковой допустимой норме CTX имеет благоприятную оценку для NLL A,
но доверительный интервал включает ноль и выходит за пределы ±0,01.
Данных недостаточно и для `DIRECTION_SUPPORT`, и для `SCALE_ONLY`.
Польза одной записи B на уровне вероятности подтверждена. При той же силе
записи CTX уступает RAW по улучшению B и не добавляет правильных ответов.
Преимущество, достаточное для перехода к новому протоколу совместного
обучения, не установлено. C1 остаётся закрытым.

## Допустимость сопоставления норм

| Плечо | Допустимо | `INFEASIBLE_MATCH` |
|---|---:|---:|
| NONE | 54 | 0 |
| RAW@raw | 54 | 0 |
| CTX@raw | **1** | **53** |
| RAW@ctx | 54 | 0 |
| CTX@ctx | 54 | 0 |

Все 53 невозможных случая CTX@raw выходили за исходный покомпонентный
cap на луче CTX. Данные не перепроектированы. Во всех 54 случаях исходная
норма RAW превосходила исходную CTX. Их средние нормы равны 1,3778 и
0,8264. Поэтому заранее предусмотренный меньший радиус для каждого случая
совпал с его собственной нормой CTX. Полное сравнение обоих направлений
возможно только при меньшем радиусе. На большем радиусе один блок
даёт лишь описательный пример, ДИ по этой паре и взаимодействию отсутствует.
Нулевых и нечисловых кандидатов не было.

Предложенные компоненты не превышали 0,50. Максимум при численном
вычитании хранимых матриц `0.5000000000000001` соответствует округлению.
Максимальное относительное расхождение фактических норм в паре
`3.57e-16`. Исходные RAW и CTX воспроизведены побитово на записанном токене.

## Равная сила записи и перенос на другие токены

Каждое значение ниже — CTX минус RAW при одной и той же меньшей норме
конкретной записи. Положительная разность NLL означает худший ответ CTX.

| Срез | Парная ΔNLL | 95% ДИ | Парная Δmargin |
|---|---:|---:|---:|
| A, записанный токен | −0,01411 | от −0,02947 до +0,00199 | +0,06375 |
| B, записанный токен | +0,11125 | от +0,04464 до +0,18807 | −0,13884 |
| A, другие токены | +0,00061 | от −0,00488 до +0,00586 | −0,00093 |
| B, другие токены | +0,02774 | от +0,01072 до +0,03874 | −0,02751 |

В raw-направлении переход от меньшего к большему радиусу ухудшил NLL
того же токена A на +0,01857 (95% ДИ от +0,00445 до +0,02964) и улучшил
NLL B на −0,23399 (от −0,33478 до −0,09881). Средний margin A уменьшился
на 0,08540. Это прямое указание на вклад масштаба. Исходные направления
записи B для RAW и CTX различаются. Их средний косинус равен 0,643.

Относительно NONE исходный CTX оставил NLL того же токена A около нуля
(−0,00075 с ДИ от −0,00383 до +0,00334). На **других** токенах A NLL
выросла на +0,00404 (от +0,00050 до +0,00801), ухудшились 171 из 270
чтений (63,33%). Средний margin этих токенов уменьшился на 0,02410.
Потерь правильного класса у A не было. Локальная стабильность записанного
токена скрывает небольшой перенос по уверенности на остальные токены.
Данные не показывают надёжной разницы между направлениями по NLL других
токенов A на совпадающей норме. Для других токенов B CTX уступил RAW,
а сравнение CTX с NONE имеет ДИ, включающий ноль.

## Сколько пользы осталось для B

| Плечо | ΔNLL B того же токена к NONE | 95% ДИ | Правильных B из 54 |
|---|---:|---:|---:|
| NONE | 0 | — | 2 |
| RAW@raw | −0,59303 | от −0,88311 до −0,28443 | 11 |
| RAW@ctx | −0,35904 | от −0,54745 до −0,18562 | 4 |
| CTX@ctx | **−0,24779** | от −0,35657 до −0,14098 | **2** |

CTX прибавил +0,295 к margin B относительно NONE. При равной норме
его NLL-выигрыш сохранил около 69% улучшения RAW, но correctness осталась
2/54 и ни одного нового B-класса не появилось. RAW на том же радиусе
дал два новых правильных ответа. У CTX установлена меньшая польза для B
на одинаковой норме. Полный `TRADEOFF` как сочетание установленной защиты
A и установленной цены для B остаётся неподтверждённым из-за интервала A.

## Сверка состояния и контролей

Испытаны 9 A-only снимков и 54 независимых одношаговых записи. Подтверждены
190 точных возвратов полных состояний в основной панели. Первый блок
побитово повторён после предварительной сверки, включая логиты, журналы
действий и массивы предложенных и фактических ΔK. Совпали RNG всех парных
чтений. Девять целевых тестов прошли. Израсходовано 314 304 подшага на
основной прогон и 36 288 на предварительный блок.

На 12-парной пробе K0 дала 25,93% для A и B. Чужая A-only K дала 33,33%
для A и 18,52% для B. Собственная A-only K в NONE дала 100% и 3,70%.
Контроли K0 и чужой K из сравнения норм исключены. Ни одна диагностическая
запись не продолжала обучение основной ветви. C1, DREAM, N/F, M5 и новые
панели не запускались.

## Протокол и исходное состояние

База D0–D3 `b8fc818cdcface65d1410d9197aaaf60773a5e9d`, исполняемый SHA
`0d4644a2c36147e5f110f275641ab8780d7f32dd`. Сверены весь манифест исходной
поставки, SHA-256 ZIP и побитовое совпадение вложенных исходников с
`git archive` исполняемого коммита. План, исходники, бриф и правила
интерпретации записаны в `LOCK.json` до предварительной проверки.

Испытание использует девять прежних A-only снимков `separate/raw SS`.
Каждый из шести токенов образует отдельное свидетельство B из того же
снимка. Подтверждённая метка раскрывается после записи прогноза и действия.
Исходные направления вычислены из той же ошибки B и тех же сенсорных
признаков, что в D1/D2. Для каждого случая проверены пять запрошенных
условий. NONE использует базовый результат, общий для шести независимых
вмешательств одного снимка. K0 и чужая K из A-only соседнего mapping
при том же seed служат отдельными отрицательными контролями.

В каждом допустимом плече единственное изменение — копия K после одной
записи. Пробы проверяют 12 сочетаний на независимых ветвях из Z0-64.
Сохраняются неизменные B/W/A, физические параметры и RNG. После подмены
и проб состояние копии возвращается к полному снимку. Норма считается
по хранимой разности K после сложения. Исходный покомпонентный cap — 0,50.
Элементы предложения выше cap запрещены. Четыре ulp, описанные в методе,
относятся к вычитанию хранимых чисел. Для всех допустимых пар проверено
совпадение фактической нормы с относительным допуском `1e-12`.

Невозможное сопоставление отмечается `INFEASIBLE_MATCH`. Весь набор
незаполненных точек остаётся в `D4_MATCHES.csv`. Пары при меньшей из
исходных норм дают заранее предусмотренное сравнение на полной панели.
95%-интервалы построены по девяти блокам с раздельным ресэмплированием seed
и mapping. Строки токенов не трактуются как независимые блочные наблюдения.

## Воспроизведение

Архив включает исходную поставку `D0_D3_ORIGINAL.zip`, неизменённый
`D4_HANDOFF_ORIGINAL.zip`, Git bundle и точный `FROZEN_CODE.zip`, полные снимки
и батареи логитов, исходные и фактические ΔK. `D4_PER_TOKEN.csv` содержит
метки, NLL, margins и argmax для каждого доступного чтения. `D4_PER_BLOCK.csv`
содержит четыре среза каждого парного контраста. `D4_ECHELONS.csv` раскрывает
все пары эшелонов. Манифест SHA-256 охватывает файлы поставки.

Клонировать `D4_SOURCE.bundle` с веткой `exp/life-qnuf-context-bind-d4`.
`$reference` указывает на распакованный `D0_D3_ORIGINAL.zip`, `$archive` —
на этот ZIP, `$handoff` — на `D4_HANDOFF_ORIGINAL.zip`, а `$run` — на новую
папку. После клонирования выполнить команды.

```powershell
python -m pqt_qcat.memory.qnuf_context_d4 init --output $run --reference $reference --archive $archive --handoff $handoff
python -m pytest pqt_qcat/tests/test_qnuf_context_d4.py pqt_qcat/tests/test_qnuf_tworule.py pqt_qcat/tests/test_sidecar_causal.py -q
python -m pqt_qcat.memory.qnuf_context_d4 preflight --output $run
python -m pqt_qcat.memory.qnuf_context_d4 run --output $run
python scripts/analyze_context_d4.py $run
python scripts/plot_context_d4.py $run
```

Для read-only сверки сохранённой поставки выполнить
`python scripts/analyze_context_d4.py $archivedRun --reference $reference --verify-only`.
