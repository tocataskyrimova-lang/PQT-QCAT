# LIFE-QNUF-F0B-COVERAGE-001 · причинная диагностика покрытия

**Научный вердикт `CANDIDATE_SET_LIMITED`. Инженерный вердикт `F0B_VALID`. F1 и C1 закрыты.** Более широкий банк устранил скрытый ущерб в прогонах F0. Он сохранил ровно два безопасных исправления текущего B из тех же двух случаев исходного банка. При полном покрытии остальные 50 исходно ошибочных ответов не исправляет ни один из шести кандидатов с заданным допуском A.

## Размер банка

Вложенная серия использует первые подтверждённые токены A в каждом блоке. `ALLOW` означает выбор исходного RAW, `REPAIR_PASS` означает выбор альтернативы, `BLOCK` оставляет K исходной. Каждая строка относится к тем же 54 одиночным вмешательствам. Доля скрытого ущерба дана среди записей, которые прошли допуск. Оба столбца «новый B» считают переход ошибки в правильный класс при снижении NLL минимум на 0,10.

| 3 | 10 (18,5%) | 16 (29,6%) | 28 (51,9%) | 3 | 2 | 5/54 | 15/26 (57,7%) |
| 4 | 8 (14,8%) | 15 (27,8%) | 31 (57,4%) | 3 | 2 | 5/54 | 10/23 (43,5%) |
| 5 | 5 (9,3%) | 16 (29,6%) | 33 (61,1%) | 3 | 2 | 5/54 | 4/21 (19,0%) |
| 6 | 2 (3,7%) | 16 (29,6%) | 36 (66,7%) | 2 | 2 | 4/54 | — |

Переход с 3 к 6 заменил 7 из 15 записей со скрытым ущербом допустимыми альтернативами и заблокировал ещё 8. Все 18 выбранных записей полного банка выдержали допуск по шести известным A. Только две исправили класс текущего B. Другие 16 снизили NLL текущего B и сохранили ошибочный ответ. Без записи правильных B было 2/54. Точность на остальных пяти B осталась 10/270 во всех четырёх банках. Ни один из 324 правильных ответов A не потерян в основной серии. При шести A диагностической области вне банка нет.

На снимке `821103 / mapping 2` для записи `B:1` удалённый из банка `A:1` потерял +0,315929 по NLL при росте полезности B по NLL и сохранении его ошибки. Этот контрпример сохранялся во всех вложенных банках до пяти токенов. Полный банк исключил запись с таким ущербом. Поэтому расширение банка снизило частоту пропусков, а наихудший ущерб оставался тем же, пока конкретное свидетельство отсутствовало.

При трёх токенах банк `126` пропустил 6 случаев ущерба из 22 допущенных, банк `234` пропустил 29 из 36. Среди пяти токенов маска `12456` дала те же 54 решения, что и полный банк. Маска `12345` пропустила ущерб в 10 из 24 допущенных случаев. Равенство решений маски `12456` с полным банком относится к проверенным сценариям и не устанавливает, что токен 3 избыточен при другом опыте.

## Осуществимость и компромисс

Для 52 исходно ошибочных B выполнен исчерпывающий перебор **в пределах шести фиксированных кандидатов F0**. В **43/52** случаях ни один кандидат не дал новый правильный класс B даже без ограничений A. В **7/52** подходящий для B кандидат нашёлся, но каждый такой кандидат выходил за допуск хотя бы на одном из шести A. В оставшихся **2/52** нашлись совместно допустимые записи. Это случаи `821101 / mapping 2 / B:2` (RAW_SMALL, MIX25, MIX50) и `821101 / mapping 2 / B:4` (RAW). Полный банк и исходный основной банк выбрали RAW_SMALL и RAW соответственно. Полный банк нашёл все совместно осуществимые случаи при исходном порядке перебора.

По зафиксированному разложению `L=9`, `J=2`, `G3=G6=2`. Утрата возможности из-за конфликта с A (`L−J=7`) превысила вклад покрытия в безопасное приобретение (`G6−G3=0`) и разрыв отбора (`J−G6=0`). Недостаточное покрытие объясняет ложные допуски F0. Дефицит кандидатов объясняет отсутствие дополнительных безопасных исправлений B. Заключение ограничено конечным набором направлений и норм.

При допуске ΔNLL A в 0,02 полный банк разрешил 32 записи после 18 при 0,01 и сохранил те же два исправления B. Увеличение допуска до 0,05 дало четыре исправления, до 0,10 дало семь, до 0,25 дало девять. При 0,25 максимальный фактический рост NLL A составил +0,15763, а 45 из 47 выбранных записей нарушили исходный предел 0,01. На всех 11 предписанных порогах число реально выбранных исправлений B совпало с числом случаев, в которых такое исправление было доступно среди кандидатов.

## Инженерная проверка и стоимость

- Исторические подтверждения для всех шести A каждого блока сверены с реестром checkpoint и журналом действий. Для каждой маски выбор получил только баллы её A и результат проверки текущего B после сохранённого действия. Реестр 2268 решений был записан до расчёта показателей вне банка. Все 54 решения исходного F0 воспроизведены. Отдельная реализация пересчитала 2268 решений и 11 точек кривой из `F0_PER_QUERY.csv`.
- В F0B эпизодно воспроизведены **324 записи K с точным восстановлением полного снимка** на всех девяти checkpoints. Во время вмешательства весь снимок, кроме K, совпадал с исходным. **189 новых чтений**, по три запроса на семь условий с NONE на каждом снимке, дали точное совпадение логитов и RNG с архивом. Эти чтения заняли 24 192 подшага интегратора. Прочие оценки масок использовали уже проверенные замороженные логиты. Геометрия, фактическая норма ΔK, исходный cap 0,50 и float64-допуск проверены по массивам F0 для всех кандидатов.
- При вычислении заново политика банка из 3, 4, 5 и 6 токенов требует соответственно 191 808, 234 432, 277 056 и 319 680 подшагов на всю панель. Включены исходный прогноз, признаки и повторные проверки банка и текущего B для всех кандидатов. Число чтений кандидатов составляет 1296, 1620, 1944 и 2268. Полный банк добавляет 66,7% подшагов относительно трёх токенов. Эти числа относятся к одной политике на один размер банка. Сам перебор составов повторно использовал логиты. Целевые регрессии F0, D4 и TWORULE прошли **10/10**.

Условие защиты банка, защита всего известного A и обобщение различаются экспериментально. Токены A вне конкретной маски исключены из выбора записи, но уже входили в 48 наблюдений A-only. Полный банк проверяет шесть известных токенов при замороженном чтении Z0-64. Остальные пять B позволяют наблюдать межтокенные эффекты после одной записи. Обобщение на новые задачи, чтение из рабочего Z и последовательное обучение в F0B не измерялись. F1, C1, DREAM, M5, новые финальные seeds и перестройка архитектуры не запускались.

## Поставка и повтор расчёта

База `72379f393ffa35909712e80311008930203f3f5a`, точный код расчёта `c11d2770a8087c150eb3f292509400a7b04e674c`. `PLAN.json` хранит все маски и полученные подтверждения, `LOCK.json` фиксирует план и протокол, `DELIVERY.json` хранит полный SHA коммита поставки. `F0_ORIGINAL.zip` сохраняет исходную поставку F0 со снимками, кандидатами и журналами. `ARTIFACT_MANIFEST.sha256` покрывает файлы поставки, включая оригинальный архив. До расчёта и после упаковки проверены SHA-256 и Git-происхождение.

Быстрая проверка требует распаковать поставку F0B, затем `F0_ORIGINAL.zip` в отдельный каталог и клонировать `F0B_SOURCE.bundle`. Пример для Windows с заменой путей.

```powershell
$run = 'C:/work/f0b'
$f0 = 'C:/work/f0'
$code = 'C:/work/f0b-code'
git clone -b exp/life-qnuf-f0b-coverage-001 "$run/F0B_SOURCE.bundle" $code
Set-Location $code
python scripts/verify_f0b_coverage.py $run $f0
```

Для полного повторения распакуйте также `D4_ORIGINAL.zip` из F0, используйте сохранённые версии зависимостей из `SOURCE.json` исходного архива и задайте новый выходной каталог.

```powershell
$d4 = 'C:/work/d4'
$newRun = 'C:/work/f0b-replay'
git switch --detach c11d2770a8087c150eb3f292509400a7b04e674c
python scripts/f0b_coverage.py freeze --out $newRun --input $f0 --archive "$run/F0_ORIGINAL.zip" --reference $d4
python scripts/f0b_coverage.py run --out $newRun --input $f0 --archive "$run/F0_ORIGINAL.zip" --reference $d4
git switch exp/life-qnuf-f0b-coverage-001
python scripts/verify_f0b_coverage.py $newRun $f0
```
