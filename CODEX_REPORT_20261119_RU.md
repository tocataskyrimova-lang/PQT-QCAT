## Главный результат

**В проверенном CARRY-режиме не подтверждено предположение, что полезная память
уже надёжно записана в K и проблема состоит только в штатном считывателе.**
Независимый внешний линейный decoder извлёк правильные ответы лишь в 24,48% случаев.
При этом тот же класс decoder после обучения со сбросами достиг 91,67%.

Это не доказательство отсутствия любой информации в CARRY-K: нелинейный или лучше
обученный decoder может извлечь другие признаки. Но перенос прежнего результата
«K декодируется на 100%» из RESET-обучения на непрерывную жизнь экспериментально
не обоснован. Простой сброс Z после CARRY здесь не помог, а ухудшил accuracy.

**Вердикт по текущей исследовательской гипотезе: PARTIAL.** Исправления сохранения
и диагностики проверены. Цель непрерывного освоения и удержания правил не достигнута;
gate 75% для CARRY не пройден. Вклад A и восстановительная функция сна этим опытом
не исследовались. Большой функциональный R4 не объявляется успешным.

## 1. Что исправлено и проверено

1. Полный checkpoint v2 с атомарной записью NPZ без pickle. Сохраняются тип агента,
   все его веса, состояние ядра, physical config, параметры потенциала/вихря,
   integrator config, gamma, substeps, RNG, traces, pending prediction и runner cursor.
2. Восстановление JointAgent теперь включает W_readout_c0/W_readout_c1. Повтор прежнего
   дефекта на seed 42, 72 события: **100% до save/load → 100% после**, логиты побитово
   одинаковы. K в этом baseline действительно остаётся замороженной.
3. Strict restore отклоняет несовместимые настройки, включая substeps. Non-strict
   restore пересоздаёт зависимые объекты интегратора. Передача RNG ядра в stochastic
   step исправлена и отдельно проверена при ненулевой температуре.
4. Проверено продолжение в новом процессе после сохранения между прогнозом и feedback,
   с ненулевой eligibility trace. Отдельно восстановлена настоящая жизнь основного
   опыта из checkpoint 24: **все 72 event records и все поля конечного checkpoint
   совпадают** с непрерывным выполнением.
5. Предложенное и реально применённое ΔK разделены. Исторический Direct_Context_Gating
   явно остаётся baseline двух обучаемых readout с frozen K; пластичная K — отдельный
   opt-in вариант, его преимущество здесь не заявляется.
6. Энергия вычисляется существующим функционалом для шести 8D cells. Сумма cell
   potentials — диагностическая величина, не доказанный Lyapunov functional всей
   связанной системы. Overflow обозначается отдельным признаком, а не нулём.
7. Исправлены шаблоны четырёх legacy-отчётов: они больше не печатают заранее
   прописанные «100% на всех seeds», необходимость gating/демпфирования, превосходство
   agreement-токенов или достаточность шага без проверки данных. Старые отчёты
   в исходном worktree не перезаписывались.
8. Обнаружен старый тест manifest, который писал в prereg. Исторические файлы новой
   копии восстановлены из базы; тест переведён на tmp_path и дополнен проверкой
   обнаружения испорченного файла. Diff prereg относительно базы отсутствует.

Полный прогон: **116 passed**, 805,18 с, одно предупреждение зависимости pynvml.
Он начался до добавления последнего теста stochastic RNG. После последних изменений:
**19 passed**, включая этот новый тест и исправленный manifest test. Это два прогона
с пересекающимся составом; их количества не складываются как независимые тесты.
XML результатов сохранены. Глобальные зависимости не устанавливались и не изменялись.

## 2. Протокол опыта

Полный машинный план: `PLAN.json`; текст: `CODEX_MEMORY_LOCATION_PROTOCOL_RU.md`.
Первый RUN_A закрыт **до обучения**, когда preflight выявил неполную передачу RNG.
RUN_B зафиксирован заново до данных; выборки и learning hyperparameters не подбирались
по результатам основного опыта.

| Элемент | Зафиксированное значение |
|---|---|
| Задача | Одно отображение 6 запросов в 4 класса на жизнь |
| Режимы обучения | CARRY_TRAIN и RESET_TRAIN |
| Длительность | 72 сбалансированных события на жизнь |
| Предъявление | ctx ticks=0; query ticks=8; gate=1 |
| Интегратор | Fixed Heun, 2 подшага по 0,005 на физический tick |
| Пластичность | Исходное target-only правило, eta=0,8, clip=0,5 |
| Development | 2 seeds × (12 fit maps + 4 tune maps) × 2 режима = 64 жизни |
| Holdout | 4 новых seeds × 8 новых maps × 2 режима = 64 жизни |
| Все данные | **128 жизней, 9 216 событий**, отказов нет |
| Checkpoints | 0/24/48/72: **512 полных снимков**, плюс latest-копии |
| Reader | 6 RidgeClassifier на 144 активных координатах K, отдельно по режимам |

24 отображения уникальны. Fit/tune/holdout mappings не пересекаются; holdout seeds
отделены от development. Fit покрывает все четыре класса для каждого query.
Alpha выбирался только на tune, затем model refit на всём development.
До запуска holdout записаны coefficients/classes/intercepts и SHA256 reader.
Контроль majority обучен по development, а не выбран по holdout-меткам.

Для каждого checkpoint живое и reset-чтение выполняются на одинаковых независимых
клонах, по одному на query. В reset probe меняется только Z/trace; K/B/W не меняются.
Probe не обучает модель и не меняет тренировочную ветвь. Даже для RESET-training
live probe не сбрасывает сохранённое Z: это отдельная диагностическая интервенция.
Штатная финальная оценка RESET-training соответствует столбцу «после сброса Z».

Результат на holdout оценивается по 4 seeds × 8 mappings. **192 query-ответа на режим
не считаются 192 независимыми наблюдениями.** ДИ: двухфакторный paired bootstrap,
5000 реплик. Перестановки: 999, единица — mapping совместно для всех seeds.
При малом числе независимых уровней интервалы приближённые.

## 3. Независимая панель: итоговые числа

| Способ чтения / контроль | После CARRY-обучения | После RESET-обучения |
|---|---:|---:|
| Штатное чтение из сохранённого живого Z | **32,29%** | 35,42% |
| Штатное чтение после сброса Z при тех же K/B/W | **16,67%** | **79,69%** |
| Внешний reader K_after | **24,48%** | **91,67%** |
| Внешний reader ΔK | 25,52% | 91,67% |
| Внешний reader K_initial | 27,60% | 27,60% |
| Development-majority baseline | 27,08% | 27,08% |
| Online accuracy за 72 события, до feedback | 28,78% | 54,64% |

Парные контрасты, процентные пункты:

| Контраст | CARRY: среднее [95% ДИ] | RESET: среднее [95% ДИ] |
|---|---:|---:|
| Reset probe − live probe | −15,63 [−21,88; −10,42] | +44,27 [+22,38; +64,06] |
| Reader K_after − live probe | −7,81 [−18,23; +3,13] | +56,25 [+46,88; +65,63] |
| Reader K_after − reader K_initial | −3,13 [−15,63; +9,90] | +64,06 [+52,08; +76,04] |

Группированный permutation p для frozen K_after reader: **0,519** в CARRY,
**0,001** в RESET. Последнее — минимальная plus-one оценка при 999 перестановках,
а не точная вероятность универсального утверждения о памяти.

Mean ||K_after−K_initial||: **40,18 в CARRY против 8,12 в RESET**. Большое изменение
весов само по себе не означает полезное обучение. Это наблюдение не доказывает,
что причиной ошибки служит именно норма K или конкретный блок самосвязей.

На holdout максимальная наблюдаемая норма состояния после физических подшагов:
15,68 в CARRY и 2,49 в RESET. Численных отказов нет; это ограниченная панель и
горизонт, а не доказательство глобальной устойчивости.

## 4. Что теперь известно о механизме

1. При RESET-training получены и хорошее native reset-чтение, и сильный внешний reader.
   Следовательно, диагностический decoder способен извлекать информацию на этой
   панели и не является заведомо неработающим отрицательным контролем.
2. При CARRY-training тот же класс независимого reader не показал преимущества
   над K_initial. Ни живое, ни reset-чтение не достигли освоения правила.
3. Из этого нельзя выбрать единственную причину между недостаточной полезной записью,
   нелинейным/непереносимым кодом в K и ограничениями reader. Но гипотеза «сохранённая
   K столь же хороша, как после RESET, исправить надо только Z/readout» поддержки
   в данном опыте не получила.
4. Необходимость A, преимущества перед GRU/LSTM, польза DREAM, долговременное удержание
   нескольких правил и непрерывная языковая генерация не проверены. Эти цели нельзя
   выводить из положительного контрольного плеча.

**Следующий причинный вопрос относится к записи и представлению памяти в CARRY,
а не к заранее принятому факту успешной записи.**

## 5. Проверяемое направление v0.2

Фундамент v0.2 уже реализован технически: постоянное состояние, online feedback,
точный checkpoint всего обучаемого состояния, независимые read probes и явный
учёт того, где меняются параметры. Успешную функциональную v0.2 объявлять рано.

Следующая development-развилка должна разделить два изменения при сохранении A/Z:

- Центрирование eligibility по изменению признаков за событие вместо накопленного
  общего смещения; отдельно — сравнение исходного target-only и полного class-error.
- Контроль пластичности K[E5,E5] отдельной интервенцией, без одновременного изменения
  readout, контекстного кодирования и длительности запроса.

Это кандидаты, **не установленные причины и не уже выполненные улучшения**.
Сначала нужен CARRY-positive control на одном правиле, затем joint rules, затем
длительность/idle/consolidation. Для сравнения оставить простой context-head baseline
и readout на простых query-признаках: выигрыш от добавленной памяти не приписывать A.
Новая конфирмация требует новой заранее выделенной панели; использованные здесь
seeds/mappings больше не являются нетронутыми. M5 остаётся закрытым.

## 6. Воспроизводимость и ограничения поставки

Основной научный запуск занял **825,54 с wall (13,76 мин)** при одном worker.
Сумма измеренного CPU-времени задач-жизней — **434,63 с**; она не включает все
тесты, импорты, fitting и отчётность, поэтому не названа полным CPU-бюджетом работы.
Во время общего тестирования одновременно работал один научный worker. Зафиксированы
версии NumPy/SciPy/sklearn/PyTorch/pytest. Артефакты содержат события, features,
веса reader, logits/predictions, snapshots, hashes и результаты независимой проверки.

Скрипт `verify_memory_run.py` перепроверил все 9 216 событий, фактические изменения
матриц, итоговые accuracy, features из checkpoints и hash frozen reader.
`verify_life_resume.py` проверил реальное продолжение с середины в новом процессе.

После основного опыта изменены только тест manifest, текстовые шаблоны отчётов и
представление nonfinite-диагностик вспомогательного convergence runner. Обучение
основного опыта не перезапускалось и его метрики не подменялись. Точные использованные
исходники сохранены в `SOURCE_CODE.zip`, их хеши — в `SOURCE.json`. Изменения текущих
файлов относительно frozen snapshot явно перечислены независимым verifier.

Вспомогательный convergence run потребовал повторения: при заведомо неустойчивом h
overflow максимума был правильно обнаружен, но строгая JSON-запись его отвергла.
Диагностика переведена на null плюс явный overflow flag. Отдельная попытка импорта
упёрлась в MemoryError при параллельном тестировании; повтор выполнен последовательно
с ограничением потоков. Основной MEMORY-LOCATION run от этого не зависел.
История попыток сохранена, неуспешная временная запись не выдаётся за полный результат.
Повтор завершён: h=0,01 снова падает на event_idx=50; h=0,005 и h=0,0025
завершают 72/72 события. Максимумы суммы cell potentials по подшагам для двух
устойчивых запусков — **46,82 и 51,92**, а не фиктивный ноль. Для неустойчивого
запуска записаны `max_energy_all_substeps=null` и `energy_nonfinite_observed=true`.
Эта проверка не устанавливает универсальную достаточность шага для иных задач.
