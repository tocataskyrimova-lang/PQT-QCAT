# LIFE-003 / T1-FIX-004 — RC4

Основание — RC3, коммит `66d84eed8aad6a97b41c8988ef02a520b5a2ea28`. Область проверки — T1. Эпистемический статус — `W_CANDIDATE`, `proof_claim = false`.

## FIX-2. Формат чекпойнта

RC4 хранит словари как пары типизированных ключей и значений, а каждый массив — под отдельным порядковым номером внутри NPZ. Имена полей пользовательского объекта не участвуют в выборе имени файла массива. Кодирование различает bytes, bytearray и tuple. Для неподдерживаемого типа сохранение завершается ошибкой до замены целевого файла.

Архив содержит версию формата и SHA-256 исходного состояния. Запись создаёт временный файл, загружает его с проверкой исходного хеша и только после этого заменяет целевой файл. Загрузчик сверяет вычисленный хеш с сохранённым. Для проверки по внешнему эталону предусмотрен параметр `expected_state_hash`. Он обязателен при чтении архивов RC3, которые не содержат исходного хеша. Для опубликованных архивов RC3 эталоны доступны в `results/THOUGHT_LOOP_T1/resume_verification.json` на теге RC3.

## FIX-3. Подтверждение гипотезы

Регистрация, повышение статуса и восстановление `SUPPORTED` требуют валидного Ledger, существующей записи VERIFIED_FEEDBACK, положительного булева подтверждения, непустого результата, совпадения идентификатора, происхождения, действия и области применимости. Числовой support_score из записи должен достигать порога COMMIT действующей конфигурации. SANKALPA использует ту же функцию проверки данных и оценки. Отрицательная обратная связь по-прежнему может регистрироваться как отрицательная.

При восстановлении организм сначала проверяет Ledger и пул гипотез. Непроверяемая поддержанная гипотеза вызывает исключение до применения состояния организма. Область применимости заявки должна быть задана независимо от области в свидетельстве.

## Воспроизведение

Из 57 сценариев RC3 три положительных примера предполагали поддержку без области применимости. В тестовых данных этих сценариев теперь задана область DOMAIN_A. Исходные проверки поведения сохранены. В `tests/test_t1_fix004.py` добавлены отдельные случаи для контрпримеров RC3, повреждения архивов, политики порога и восстановления с отсутствующим или неподходящим свидетельством.

```powershell
python -B -m pytest tests/test_continuous_life.py tests/test_t1_fix004.py -v -p no:cacheprovider
python -B -c "from scripts.run_t1_heartbeat import run_t1_experiment; run_t1_experiment(output_dir='../rc4-replay')"
```

Ожидаемые результаты — 57 исходных сценариев и 68 новых проверок. T1 создаёт девять файлов, включая шесть NPZ и поток из 8 250 строк. При продолжении с тика 5000 выполняются 4 125 вызовов планировщика и 5 000 физических шагов, в том числе 875 внутренних шагов запросов. Конечный хеш состояния — `0f3418870285f58f68a659dda70daa1e5f82d3165d155de98957216f3b4dda4a`. Контрольные суммы файлов приведены в SHA256_MANIFEST.json.
