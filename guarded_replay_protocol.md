# Защитный replay: дополнительный тест после причинной диагностики

Исходные50 жизней и12 temporal runs не заменяются. Их default guarded_replay
остаётся False. Защита проверяется отдельно на новых seeds701–703.

Гипотеза: сохранённые eligibility features могут устаревать. Наивный replay
изменяет решение на актуальных представлениях, даже улучшая старый пример.
Каждые200 ticks в shadow core заново кодируются ранее наблюдавшиеся
context/token с уже полученными labels. Shadow не заменяет active state.
Предложенное фоновое обновление принимается только если BCE этого контекста
на anchors не выросла и число правильных anchors не уменьшилось.

Это bounded empirical guard, не глобальная гарантия: anchors ограничены
прошлым опытом, могут быть нерепрезентативны или содержать устаревшие labels.
Расход дополнительных shadow-ticks явно учитывается. Никаких target из
финальных query при проверке guard не используется.

Три ветви одного snapshot после того же online обучения без консолидации:
naive replay, guarded replay, no replay. Каждая10000 idle ticks, затем
одинаковые query. Базовая no-idle ветвь. Дополнительно default PQT c guard
в полном непрерывном протоколе на тех же новых seeds, отдельно от primary.
