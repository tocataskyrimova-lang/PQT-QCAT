# Итоговая фиксация после development, до seeds101–105

Development: seeds11 и12. Сравнены learning_rate .3/.8/1.5 на seed11;
выбрана средняя .8, давшая устойчивое позднее решение на обоих development
seed. Остальные выбранные параметры находятся в Config. Это инженерная
разработка, а не утверждение заранее известного успеха.

Основной поток на пяти новых seeds101–105: A/B/C/D по500 событий,
64 query без feedback на контекст; парная копия snapshot без idle;
10000 idle ticks; те же queries; 32 свободные генерации по8 символов;
новый контекст A_v2 с500 событиями; проверка старых контекстов;
500 событий новой противоречивой версии A под прежним ID, новый/старый тест.
Feedback задержан на3 предсказания. Состояние в главной жизни не сбрасывается.
Каждый предсказанный символ фиксируется прежде, чем среда передаст target.

Все десять вариантов и пять seed публикуются: PQT, noA, leaky, frozen,
no_replay, no_consolidation, reset_core, shared_context, fixed_encoder,
no_replay_no_consolidation. Последние два добавлены для выделения роли
малого encoder-update и совокупности двух механизмов памяти.

Длинный стресс: seeds201–203, PQT/noA/fixed_encoder, 60 изменений правил,
по300 событий на изменение, три повторно используемых контекста и100 idle
ticks между изменениями. Это ограниченный тест сохранения способности
адаптироваться; не утверждение бесконечной пластичности.

Дополнительный temporal assay (seed301–303, PQT/noA/leaky/reset_core):
cue из1..7, затем query0, целевой символ определяется cue. Таким образом,
один текущий query одинаков при разных правильных ответах; сброс физического
состояния должен уничтожать информацию. 1200 online trials, delayed feedback,
потом тесты на нескольких промежутках. Результаты этого более трудного
теста не используются для повторной настройки основного эксперимента.

Отдельные проверки: уточнение substeps при одинаковом внешнем tick и
learning clock; 100000 idle ticks; точное сохранение и продолжение; JSONL
сервер действительно совершает ticks, пока stdin открыт и сообщений нет.
